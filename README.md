# FryerCare — B2B Mobile-First Commercial Kitchen Oil Service Platform

🌐 **Live Production Deployment**: [https://oil-change-phi.vercel.app](https://oil-change-phi.vercel.app/)

A mobile-first, high-performance web application engineered for **FryerCare**, a solo-operated B2B trade service that visits commercial restaurants, cafes, and food venues to filter, clean, and restock cooking oil on scheduled routes or on-demand emergency calls.

---

## 🛠 Tech Stack

- **Framework**: [Next.js 15 (App Router)](https://nextjs.org/) + [React 19](https://react.dev/)
- **Language**: TypeScript (Strict Mode — zero `any`)
- **Styling**: [Tailwind CSS](https://tailwindcss.com/) + custom design tokens (Deep Matte Charcoal `#1A1D20` & Warm Amber Accent `#E46438`)
- **Database & ORM**: PostgreSQL + [Drizzle ORM](https://orm.drizzle.team/)
- **Validation**: [Zod](https://zod.dev/)
- **Icons**: [Lucide React](https://lucide.dev/)

## 🏛 Architectural Decisions & Tradeoffs

### 1. ORM Choice: Drizzle ORM vs Prisma
- **Decision**: **Drizzle ORM** (with `postgres.js`).
- **Justification**:
  1. **Zero-overhead & Serverless/Edge Friendly**: Drizzle outputs pure, lean SQL queries without a heavy Rust binary engine or memory footprint.
  2. **End-to-End TypeScript Native Safety**: Schemas in `src/db/schema.ts` provide TypeScript types directly at compile time without a separate code-generation step.
  3. **Guaranteed Parameterized SQL**: Every query is compiled into native positional parameters (`$1`, `$2`), eliminating all SQL injection vectors by design.

### 2. Data Model: Subscription vs. One-Time Service Tradeoff
- **Tradeoff Analyzed**:
  - *Option A (Single denormalized flag on bookings)*: Simple, but causes scheduling chaos when an ongoing recurring contract (e.g. weekly Tuesday morning stop) generates discrete weekly visits on the operator's calendar.
  - *Option B (Relational Hybrid Model — Selected)*:
    - `venues`: Stores customer contact, venue type, and physical address.
    - `subscriptions`: Represents the recurring route agreement (weekly/bi-weekly/monthly, preferred day, base rate).
    - `service_visits`: Represents discrete appointments (either one-off or generated by a subscription), tracking job status, scheduled date/time, and technician route notes.

### 3. Operator Authentication & Route Protection
- **Approach**: Lightweight, secure HMAC-SHA256 session token system using Web Crypto API.
- **Session Management**: Stored in a secure `httpOnly`, `SameSite=Lax`, `path=/` cookie (`fryercare_operator_session`).
- **Route Guard**: Next.js Edge Middleware (`src/middleware.ts`) protects `/dashboard/*`, redirecting unauthenticated requests to `/login?redirect=/dashboard`.

## 🔒 Security & SQL Injection Defense

1. **Mandatory Parameterized Queries**: Zero string concatenation across all database interactions.
2. **Boundary Validation**: Every API payload is parsed and sanitized with strict Zod schemas (`bookingSchema`, `inquirySchema`).
3. **Safe Numeric & Enum Constraints**: Numbers are constrained to integer bounds (1–20), and frequencies/types are validated against strict whitelists.
4. **Resilient Data Store**: Includes local fallback persistence during headless development testing.

## 🚀 Getting Started

### 1. Prerequisites
- Node.js 18.18+ or 20+
- PostgreSQL (or uses built-in resilient local data store)

### 2. Installation
```bash
git clone <repository-url>
cd oilchangeProj
npm install
```

### 3. Environment Variables
Copy `.env.example` to `.env`:
```bash
DATABASE_URL="postgres://postgres:postgres@localhost:5432/fryercare_db"
OPERATOR_SECRET="fryercare-secret-key-change-in-production-2026"
OPERATOR_EMAIL="operator@fryercare.com"
OPERATOR_PASSWORD="FryerCareMaster2026!"
```

### 4. Running the Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.
